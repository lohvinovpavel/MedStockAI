# `dev` environment on GCP — plan

One shared sandbox for all seven service owners: one cluster, one database, one
JWT keypair. Not production, not per-developer. Everything here is sized for
**$200 of trial credit that expires 90 days after the account opens**, whichever
comes first.

Terraform provisions GCP resources **and** the two cluster addons the app cannot
run without. Deploying the app itself stays `kubectl apply -k` — a bad rollout
should not need a `terraform apply` to fix.

---

## 0. What forced these choices

Three facts from the existing repo, not preferences:

1. **`deploy/k8s/ingress.yaml` uses `nginx.ingress.kubernetes.io/rewrite-target`.**
   GKE's built-in GCE ingress does not understand it. Without the prefix strip,
   `auth` receives `/api/auth/login` while its route is `/login` — every browser
   call 404s (Defect B, `docs/auth/auth-spec.md`). So: **ingress-nginx**, which
   means a LoadBalancer Service and a GCP forwarding rule (~$18/mo, the second
   largest line item and non-negotiable).

2. **The session cookie is set `secure=True`** (`services/auth/app/main.py`).
   Browsers silently drop Secure cookies on plain HTTP. **A dev environment
   without TLS cannot log in at all.** So: cert-manager + Let's Encrypt over a
   `sslip.io` hostname — no domain to buy, no DNS to manage, $0.

3. **The manifests read `DATABASE_URL` as a plain URL** from the `medstock-db`
   Secret — no Cloud SQL Auth Proxy sidecar anywhere. So Cloud SQL gets a
   **private IP** in the same VPC and the URL points straight at it. No manifest
   changes, no sidecar in eight Deployments.

## 1. Resources

Region **europe-west1**, zone **europe-west1-b**. Switched from us-central1
after that region ran out of Spot `e2-medium` capacity mid-rollout — Belgium is
the cheapest, best-stocked EU region and the GKE free-tier zonal credit isn't
region-specific. A *zonal* cluster is what that credit covers.

### Network
- Custom VPC `medstock-dev` + one subnet `10.10.0.0/20`, with secondary ranges
  for pods (`10.20.0.0/16`) and services (`10.30.0.0/20`) — VPC-native GKE
  requires them.
- **Nodes keep public IPs. No Cloud NAT.** Cloud NAT is ~$32/mo plus per-GB
  processing, which would be the single most expensive thing in this
  environment, spent entirely on hiding dev nodes that have no inbound ports
  open anyway. Private nodes + NAT is a production decision; make it there.
- `servicenetworking` peering range for Cloud SQL private IP.

### GKE — `medstock-dev`
- **Zonal Standard** cluster. The GKE free tier credits $74.40/mo of cluster
  management fee, enough for exactly one zonal cluster — so the control plane is
  effectively $0. A regional cluster carries the same management fee but triples
  the nodes.
- One node pool: **2× `e2-medium` Spot**, autoscaling 1–3, 20GB pd-balanced.
  Spot is ~70% off and preemption in a sandbox costs a pod restart. The eight
  services request 50m CPU / 128Mi each; two e2-mediums (~1880m allocatable)
  hold all of them plus ingress-nginx, cert-manager and kube-system with room.
- `deletion_protection = false`. This must be destroyable.
- Release channel REGULAR. Logging/monitoring left on (50 GiB/mo is free and
  seven people will need to read logs).
- **Not enabled:** Workload Identity (no pod calls a GCP API), private control
  plane, Cloud Armor, Binary Authorization, Backup for GKE. Add when something
  actually needs them.

### Cloud SQL — `medstock-dev-pg`
- PostgreSQL 16, **db-f1-micro**, 10GB HDD, zonal (no HA), 7-day automated
  backups. ~$9/mo. Backups stay on: this is a shared DB and someone will drop a
  table.
- **Both IPs.** Private IP is what the cluster uses. Public IP (~$7/mo) exists
  so teammates can reach it from their laptops through the Cloud SQL Auth Proxy
  — IAM-authenticated, so there is no authorized-network allowlist to maintain
  as seven home IPs change.
- One database `medstock`, one user `medstock` with a `random_password`.

### Artifact Registry — `medstock`
Docker repo in europe-west1. A cleanup policy deletes untagged images older than
7 days, which keeps storage inside the 0.5GB free allowance. Replaces the
`ghcr.io/medstockai/*` refs in the manifests.

### Secret Manager
- `medstock-dev-db-url`, `medstock-dev-jwt-private-key`,
  `medstock-dev-jwt-public-key`, `medstock-dev-gemini-api-key`.
- The **JWT keypair is generated by Terraform** (`tls_private_key`, RSA 2048)
  so the whole team shares one stable dev key that survives cluster rebuilds —
  that was the point of a shared environment. It lands in Terraform state; state
  lives in a private, versioned GCS bucket. Acceptable for a dev key and **only**
  a dev key: the real cluster keypair is still generated by hand per
  `services/auth/README.md`.
- The Gemini key cannot be generated. It comes in as a `sensitive` variable via
  `TF_VAR_gemini_api_key`, never in a committed tfvars.

### IAM
A `dev_members` variable (list of emails) gets `container.developer`,
`cloudsql.client` and `secretmanager.secretAccessor`. Seven people need to
`kubectl` and reach the DB; granting it in Terraform beats seven console clicks
nobody remembers doing.

### State
GCS bucket, versioned, uniform bucket-level access, public access prevented.
Chicken-and-egg: the bucket is created by one documented `gcloud storage buckets
create` before the first `init`. A bootstrap module for one bucket is more
Terraform than the problem deserves.

## 2. Cluster addons Terraform installs

Via the `helm` provider, after the cluster exists:

- **ingress-nginx** — `controller.service.loadBalancerIP` pinned to a
  Terraform-reserved regional static IP, so the sslip.io hostname never moves.
- **cert-manager** — `installCRDs=true`.

Terraform also creates the four k8s objects the manifests already reference by
name: Secrets `medstock-db`, `medstock-auth`, `medstock-ai` and ConfigMap
`medstock-jwt`. That is exactly `deploy/k8s/secrets.example.yaml`, filled in.

**The `ClusterIssuer` is deliberately NOT a Terraform resource.** It is a
cert-manager CRD, and `kubernetes_manifest` needs the CRD to exist at *plan*
time — a fresh `terraform apply` against an empty project would fail before it
ever installed cert-manager. It ships as YAML in the dev overlay instead,
applied by the same `kubectl apply -k` the team already runs.

## 3. Dev overlay — `deploy/overlays/dev/`

> Corrected during implementation. This was originally specified as
> `deploy/k8s/overlays/dev/`, which kustomize rejects: the base root is
> `deploy/k8s`, and an overlay nested inside its own base is a reference cycle
> (`candidate root ... contains visited root ...`). Restructuring the base into
> `deploy/k8s/base/` would have been the other fix, but that edits seven other
> owners' manifests and every command already documented against them.

The base manifests are production-shaped and will not run here as-is:

| Base | Dev override | Why |
|---|---|---|
| `replicas: 2` | `1` | Sixteen pods on two Spot e2-mediums for a sandbox |
| `image: ghcr.io/medstockai/*` | Artifact Registry path | Where the images actually are |
| Ingress: no host, no TLS | sslip.io host + `tls:` + `cert-manager.io/cluster-issuer` | The Secure-cookie constraint |
| — | `cluster-issuer.yaml` | See above |

The hostname depends on the static IP, which Terraform only knows after apply.
The overlay ships a `medstock-dev.REPLACE-ME.sslip.io` placeholder and the
README gives the one `sed` command using `terraform output`. Wiring a Terraform
`local_file` into the kustomize tree would dirty `git status` on every apply for
no gain.

## 4. Cost — estimate, europe-west1

| Item | $/month |
|---|---|
| GKE control plane, 1 zonal cluster | **0** (free-tier credit) |
| 2× e2-medium **Spot** | ~15 |
| 2× 20GB pd-balanced boot disks | ~4 |
| Cloud SQL db-f1-micro + 10GB HDD + backups | ~9 |
| Cloud SQL public IPv4 | ~7 |
| Network LB forwarding rule (ingress-nginx) | ~18 |
| Static regional IP (while attached) | 0 |
| Artifact Registry / Secret Manager / GCS state | <1 |
| **Total** | **~$54** |

$200 lasts ~3.7 months of continuous running — but **trial credits expire 90
days after signup regardless of balance**, so time, not money, is the real
limit.

Two levers if it gets tight, in order of effect:
1. `terraform destroy` when not in use. Everything is reproducible; only DB
   contents are lost, and `seed.py` rebuilds those.
2. Scale the node pool to 0 overnight (~$19/mo saved). The LB and Cloud SQL keep
   billing, so this is the weaker lever.

## 5. Layout

```
infra/terraform/dev/
  providers.tf   versions, backend, google/helm/kubernetes/tls/random providers
  apis.tf        google_project_service × 6
  network.tf     VPC, subnet, secondary ranges, SQL peering, static IP
  gke.tf         cluster + spot node pool
  cloudsql.tf    instance, database, user, password
  registry.tf    Artifact Registry + cleanup policy
  secrets.tf     tls_private_key, Secret Manager, k8s Secrets/ConfigMap
  addons.tf      helm_release ingress-nginx, cert-manager
  iam.tf         dev_members bindings
  variables.tf outputs.tf terraform.tfvars.example
infra/README.md  bootstrap → apply → fill placeholders → kubectl apply -k
deploy/overlays/dev/  kustomization.yaml, ingress-annotations.yaml, cluster-issuer.yaml
```

One root module, no `modules/`. There is one environment; a module abstraction
over a single caller is a layer to maintain, not a reuse win. Split it when
`staging` actually exists.

## 6. Not in this plan

- CI/CD, Cloud Build, image pushing — separate concern, and the images do not
  build in CI today.
- A `prod` environment.
- Cloud NAT / private nodes / Cloud Armor — cost, see §1.
- Cloud SQL HA or read replicas.
- Monitoring dashboards or alerting policies.
- **RLS policies.** Still unwritten (`docs/services.md` §8 #2). A shared cloud
  database makes this more visible, not less: every teammate's data will sit in
  one Postgres with tenant isolation not yet enforced. Do not demo isolation
  from this environment.

## 7. Verification bar

`terraform validate` and `terraform fmt -check` pass. `terraform plan` is not
runnable here — there is no GCP project yet — and no `apply` is attempted.
Everything past `plan` is the user's step, documented in `infra/README.md`.
