# Day 1 — 13 August · design

Both services were `/healthz` stubs. No tenant tables, no migrations, no
permissions. The day went on deciding what to build and, more importantly, what
not to.

### Use cases specified

**COMP-1** certification traffic light, **COMP-2** unknown-drug exploration,
**PP-1/2/3** substitution safety, profile assessment, and explanation. Written
with the data sources named and their constraints recorded — openFDA's
1,000 req/day per-IP limit, which feeds are keyless, which are HTML-only.

### The PHI decision

The question was whether any web interface can be trusted with patient data. The
answer: **hold none**. Not a compromise — the rules need a feature vector, not a
person, so de-identification is *sufficient* rather than a sacrifice.

Two concrete blockers made it decisive, both found by reading the existing code
rather than reasoning about it:

- `ai_cache` is **global by design** — no `hospital_id`, no RLS. A PHI-class task
  would leak across hospitals by construction, and `models.py` justifies the
  cache precisely on the promise that it never holds PHI.
- `ai.py` reaches Gemini through the **Developer API**, which carries no BAA.
  Vertex AI does. Same model, different contract.

### A rule that survived contact with the build

**News can raise yellow; only a government source sets red.** Without it an
unverified article could tell a pharmacist a drug is uncertified.

# Day 2 — 14 August · build

### Shipped

**COMP-1 — certification traffic light.** Colour derived from FDA records: red
for an expired listing, withdrawn application or ongoing Class I recall; yellow
for expiry within 90 days, a Class II/III recall, an unapproved marketing
category, or an FDA shortage. Rules in one file, so there is one place to argue
with them. `GET /status` (batch, 100 NDCs), `/certificates/{ndc}`, `/ruleset`,
plus the inventory badge — which greys out rather than blanking the shelf when
`compliance` is down.

**COMP-2 — on-demand exploration.** The obvious approach fails: openFDA's
directory lists only currently-marketed products, so re-querying it about a drug
it dropped answers nothing. Measured against 18 real unknowns — directory **0**,
label endpoint **3**, RxNorm NDC status **18**. One has been obsolete since 2012
and now renders red, which the scheduled feed could never produce.

**PP-1 / PP-2 — assessment and cohort purchasing.** Deterministic stages; hard
gates short-circuit and produce **no score**, because a number beside an absolute
contraindication invites someone to weigh it against a discount. `POST /demand`
re-routes each patient to the safest **in-class** alternative individually, and
counts those with none rather than dropping them.

**PP-3 — AI prognosis from label prose.** The model predicts the population, not
the person. Four gates: closed vocabulary, verbatim citation, pharmacist
approval, `spl_id` versioning. Real output — amoxicillin rash conditioned on
ICD-10 B27 (*"A high percentage of patients with mononucleosis…"*), lisinopril
renal failure conditioned on renal artery stenosis, CKD and heart failure. Nine
profiles, 9/9 structurally valid, all `awaiting_approval`.

### Found by measuring, not reasoning

- **A listing-expiry rule would have turned 70% of a formulary amber every
  October.** 70.5% of products share one annual expiry date. Only a two-year
  time-travel simulation caught it.
- **One rule was 99% of the amber** — 372 of 375. Splitting transient events from
  standing properties cut the alert surface to 5.
- **Red fires on 0.0% of 3,000 real products** from the directory alone. Recalls
  and RxNorm obsolescence are where red actually comes from.
- **61% of ongoing recalls cannot be joined to a drug.** A regex tops out at 40%
  and mistakes ZIP+4 codes and UPCs for NDCs — a red badge on an unrelated drug.

## Open, and blocking

1. **`audit_log_entry`, RLS policies and triggers do not exist.** Verified
   against a migrated database: 0 policies, 0 triggers, no table. `services.md`
   §1.2/§1.3 describe both as built and `phi-readiness.md` §8 lists them as
   satisfied HIPAA controls. One migration, roughly a day — the largest gap
   between what the documents argue and what the code does.
2. **The core promise has no data.** Days-of-supply needs consumption history;
   there is no source and `prediction` is a stub with 1 test. Medicaid SDUD
   (quarterly per NDC, 1991–2026) is the closest free proxy and joins on the key
   already in use — but it is outpatient dispensing, not hospital purchasing. No
   free procurement data exists at all.
3. **CI has never gated a merge** — `pull_request` and `push` are commented out.
4. **Gemini quota exhausted** (429, free tier), so extraction cannot run at
   volume.
5. **UC numbering collided** with `docs/use-cases.md`; mine are now `COMP-n`
   and `PP-n`.
